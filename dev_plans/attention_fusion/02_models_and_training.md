### Model contract

| Candidate | Trainable parameters | Fusion/readout |
|---|---:|---|
| `image_only` | 299,794 | Original image vector → classifier |
| `geo_only` | 21,266 | Geo vector → classifier |
| `raw_concat` | 316,178 | Original image and treated geo concatenated → classifier |
| `projected_concat` | 227,090 | Separate adapters and learned modality types; concatenate two tokens |
| `tokenwise_capacity` | 359,442 | Two pre-LN residual FFNs applied independently to each token; concatenate updated tokens |
| `attention_two_token` | 359,570 | One pre-LN attention/FFN block; concatenate updated image/geo tokens |
| `attention_cls` | 459,410 | Two independently initialized pre-LN blocks over CLS/image/geo; updated CLS readout |

Attention uses a batch × token × coordinate representation and attends only
within each sample. Shared same-shape components receive the M1 component seed;
their initialization is independent of learning rate and global construction
order. The two CLS blocks receive different component seeds.

Widths and training settings are supplied through configuration. The current
CLI deliberately authenticates the frozen v1 recipe rather than accepting
unrecorded command-line changes to scientific settings. Future studies can
reuse the configurable components; their governing recipe, expected counts,
audit and matrix must first be versioned. Resource settings such as device and
CPU thread count are recorded separately. Verification-only row/epoch limits
cannot silently alter a development fit.

### Inputs and development isolation

Cache preparation rechecks canonical development identities, encoder provenance
and validation-cache lineage. It joins native geo from the two authenticated
development tables using filenames and checks plot alignment. Native geo is
preserved as float64 until the selected treatment casts model inputs to float32.
Source-table
partition names do not replace the canonical 3,378/822 assignment.

Training image vectors are freshly extracted using each seed's single frozen
training-partition-adapted encoder. Validation reuses only authenticated image
vectors and identities; historical standardized geo and logits are not reused.
Raw-image bytes and decoding are recorded, and a deterministic validation-image
subset is re-extracted solely to check representation replay. The inherited
legacy BGR/439 preprocessing is preserved. Under A002, CUDA extraction uses
batch 16, cuDNN TF32 enabled and matmul TF32 disabled. Replay tolerance is `atol=1e-5`,
`rtol=1e-4`; actual discrepancies are saved with the cache.

There is no test-role argument, mixed development/test cache fallback, OOF
training-cache fallback or automatic test evaluation. The historical protocol's
sealed label-blind test identity record is used only to verify split exclusion.
Current image hashes establish extraction provenance and are checked against
the original protocol's aggregate raw-development-image fingerprint.

All full caches live under `inputs/seed<N>/`. Bounded extraction and smoke fits
live under `verification/`; they are never eligible for M3 selection. Completed
artifacts are retained and authenticated before reuse.

### Training and checkpoint interface

Development fits use the declared AdamW recipe, independent seeded shuffle
generator, fixed final epoch, and diagnostic validation history. There is no
best-epoch selection. Geo statistics are fitted only on the allowed training
rows and saved with feature order and fitting identity. The all-development
fitting primitive can fit a fresh head and geo statistics on the combined
development rows; its actual selected refits remain M4 work.

Each fit records resolved configuration, input/encoder identities, code and
environment, parameter count, runtime, metrics and row-aligned predictions.
Resume state includes model, optimizer, Python/NumPy/Torch RNGs, CUDA RNGs when
used, independent shuffle state and the completed epoch. Mid-epoch work is
replayed from the preceding saved boundary. Completed runs cannot be overwritten.

An inference bundle contains head weights, the model recipe, geo preprocessing,
class order and the encoder reference/hash. Export includes the encoder bytes
and construction metadata. Cached-vector replay does not itself prove raw-pixel
inference reproduction; raw-pixel extraction replay is checked separately.

## Reproduction commands

Run from the repository root using the `habcls` environment. These commands
describe the public interface; the verification section records what actually ran.

Inspect the complete planned workload without loading feature payloads:

```bash
python tools/run_multimodal_attention_fusion.py plan
```

Full caches were prepared using the command below. Smoke/resume verification
then used the first 32 sorted training rows from the completed seed-1 cache:

```bash
python tools/run_multimodal_attention_fusion.py smoke \
  --name m2_smoke_v2 --seed 1 --samples 32 --epochs 3 --device cuda:0
python tools/run_multimodal_attention_fusion.py resume-check \
  --name m2_gpu_resume_v1 --seed 1 --device cuda:0
```

Prepare all four complete development caches:

```bash
python tools/prepare_attention_fusion_inputs.py \
  --seeds 1 2 3 4 --device cuda --batch-size 16 --replay-rows 16 --num-threads 4
```

The extractor also supports `--verification-only --seeds 1 --limit 32` to
prepare a bounded training cache before full extraction. This optional route
still requires A002's CUDA/batch-16 settings. Verification output names must
be new; completed evidence cannot be overwritten.

M3 will use fit IDs from the saved matrix, for example:

```bash
python tools/run_multimodal_attention_fusion.py train \
  --fit-id attention_two_token__geo_native__lr_1e-03__seed1 --device cuda
```

The same invocation with `--resume` continues an interrupted fit from its saved
epoch boundary. A new scientific recipe requires its own recorded protocol;
editing an existing configuration in place causes authentication to fail.

**M2 acceptance is satisfied.** These checks establish implementation behavior,
not an accuracy benefit. All **228 M3 fits remain planned**; no test features,
labels, predictions or metrics were accessed by this development implementation.

the GPU was unavailable both inside and outside the execution sandbox:
